## 2. 职责边界（防止同一内容两处维护）

1. **PRD 只回答 Why 与范围**——目标、决策及理由、流程编排、对外契约（API/错误码）、里程碑。不复制实现细节，细节一律链接专题。
2. **专题文档回答 How**——代码骨架、配置、行为规则与实现约束（MUST）。各管一层：jwt.md 管令牌，spring-security.md 管链路，jpa.md 管数据。
3. **交叉内容只归属一个文档**，其他文档引用不复制：
   - 黑名单**机制与三张表** → 归 `jwt.md`（token 生命周期）；
   - Filter 中的黑名单**接入点**（怎么查、查到怎么办）→ 归 `spring-security.md`；
   - claims 里的 `roles` 字段定义 → 归 `jwt.md`；**roles 数据从哪来** → 归 `jpa.md`；
   - 错误码的**对外契约表** → 归 PRD；错误的**产生与转换逻辑** → 归 `spring-security.md`。
4. 新增内容不确定归属时：先查路由表，再问。

## 4. 变更铁律

- **代码行为变了、文档没变 = bug**。这是 docs as code 的底线；
- 每个专题文档底部都有「改动同步提醒」小节，提交前对照自查；
- 文档改动与代码改动放**同一个 PR**，评审时一起看。
